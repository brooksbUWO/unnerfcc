@internal A code change from this session went out for review. This means a pull or merge request, or another provider's change in internal builds. The event fires on two triggers. The harness sees the change published, or it links the session to a PR. The event fires on creation. It also fires each time the session contributes to an existing PR. These contributions include gh pr edit, close, and ready. They also include gh pr checkout. A push to a branch with an open PR counts too. So bind on every event, not just the first. Re-emission for the same URL is possible and idempotent. For provenance, the values are scraped from the command's captured output. The source is the last PR-shaped URL printed, or a gh pr view lookup. Captured output is not only the forge CLI's own text. Hook output, or files printed by the same command, can contribute to it. So treat the fields as a binding hint. Display them, but look them up against the forge with your own credential-scoped request. Do this before you route authenticated requests or trust the host. The event is best-effort, not exhaustive. No event fires in three cases: a crash before the link, gh printing no URL to a piped capture (gh pr merge), or an unrecognized forge. Keep your provider-API lookup as the source of truth. Treat this event as the trigger.
